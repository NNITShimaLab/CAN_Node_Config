# 試験手順

この文書はPC上の制御ロジック試験と、XIAOを使った実機試験を分けて記載します。ロジック試験が通っても、配線、ボタン、LED、データフラッシュの実動作を確認したことにはなりません。

## PC上で状態機械を確認する

C++14に対応するg++を使い、リポジトリのルートで実行します。

```sh
g++ -std=c++14 -Wall -Wextra -pedantic tests/protocol_test.cpp -o tests/protocol_test
./tests/protocol_test
```

Windowsで実行ファイルの拡張子を指定する場合:

```powershell
g++ -std=c++14 -Wall -Wextra -pedantic tests/protocol_test.cpp -o tests/protocol_test.exe
./tests/protocol_test.exe
```

終了コード0とPASS表示を確認します。テスト対象は実際にスケッチが使うNodeConfig.hです。

| 確認項目 | 判定内容 |
|---|---|
| LED | 0～15の全パターンで緑の点滅回数、青の先頭表示、10秒の周期境界が一致 |
| ボタン | チャタリングを無視、1回押しと2回押しを区別、長押しで繰り返さない |
| 保存レコード | 正しいレコードを採用し、反転値不一致や範囲外を拒否 |
| 同時登録 | 10台の同時要求から、0x100～0x109へ重複・空き抜けなく割り当てる |
| 所有者優先 | 既存機器と競合した候補を取り下げ、次の最小空きIDへ進む |
| 標準IDの占有 | 管理通知を使わない標準IDの通信も探索対象にする |
| 重複 | 同じ保存IDの機器をエラーにし、通常データの送信を止める |
| 管理フレーム | 未完のUIDや破損した断片で相手を確定しない |
| 空きなし・失効 | 全16ID使用時にエラー、通知が失効した後は空きとして扱う |
| 時刻 | millis相当の32ビット時刻が桁あふれしても探索時間を判定する |

テストはPC上のメッセージ配送で状態機械を動かします。実際のCAN仲裁、パケット欠落、電気的な信号品質、EEPROM書込み、LED波形は再現しません。

## XIAO向けにビルドする

READMEの手順でコアとAdafruit NeoPixelを導入し、次を実行します。

```sh
arduino-cli compile --fqbn Seeeduino:renesas_uno:XIAO_RA4M1 --output-dir build CAN_Node_Config
```

開発時に確認した最終ビルドは、Flash 59688バイト、RAM 7608バイトです。コアやコンパイラーのバージョンによりサイズは変わります。

## 2台で登録と通信を確認する

1. 基板裏面のIDが`7012760A_Y5_241018`のCAN transceiver board for XIAO RA4M1を2枚用意し、XIAOを載せて両台へ同じスケッチを書き込みます。
2. CANH同士、CANL同士、GND同士を接続し、両端の終端抵抗と電源を確認します。
3. 両台のシリアルを115200bpsで開きます。未設定ならstate=0、ID=0xFFFF、赤の通常点滅を確認します。
4. 1台目のBOOTを1回押します。競合がなければ約3.5秒後にstate=3、ID=0x100となる想定です。LEDが10秒ごとに青だけを表示するか確認します。
5. 2台目のBOOTを1回押します。state=3、ID=0x101となり、青→緑1回の表示になるか確認します。
6. 両台のrxが増え、error=0、TEC/REC=0で安定するか確認します。

書込み中は相手のCANが停止するため、残っている機器のtx_failedやTECが増える場合があります。累積値の絶対値だけで判定せず、両台の起動後に増加が止まり、rxが増えてTECが回復するかを確認してください。

## 設定解除・保存保持・衝突を確認する

| 試験 | 操作 | 期待する結果 |
|---|---|---|
| 設定解除 | 設定済み機器のBOOTを0.5秒以内に2回押す | state=0、ID=0xFFFF、赤の通常点滅 |
| 再登録 | 解除した機器を1回押す | 稼働中の機器と重ならない最小IDを保存 |
| 電源断後の保持 | 電源を切り、再投入する | BOOT操作なしで以前のIDを読み出す |
| 同時登録 | 両台を解除し、両方をほぼ同時に1回押す | 競合を調整して0x100と0x101へ分かれる |
| 重複検出 | 下記の手順で同じ保存IDの2台を接続する | error=1、通常データ停止、赤1回の繰り返し |
| 片側給電 | 基板設計で許可される給電方法に従って片側USBを外す | 残したUSB側で相手からのrx増加を確認 |

重複検出用の構成は、一方を0x100で保存して電源OFFにし、もう一方だけで解除・再登録して0x100へ設定すると作れます。両台を再接続して結果を確認した後、一方のIDを解除・再登録して復旧してください。作業前の保存IDは変わります。

保存中の電源断試験は、通常の保持試験とは別です。現行実装は保存レコードを二重化していないため、保存値の消失を許容できるテスト機器でのみ実施してください。
