# 動作仕様

対象はCAN_Node_Config.inoとNodeConfig.hの現行実装です。10台前後のXIAO RA4M1に同じスケッチを書き込み、機器ごとに通信IDを保存して利用します。

## 固有IDと通信IDを分けて扱う

| 名前 | 定義 | 変更・保存 |
|---|---|---|
| 固有ID / UID | RA4M1チップの128ビットのハードウェア固有ID | R_BSP_UniqueIdGet()で読み出す。ユーザーによる割当は不要 |
| 管理用タグ / tag | UIDのFNV-1aハッシュの下位25ビット | 管理フレームの送信元を区別するため起動時に生成 |
| 通信ID / node.id | テストデータを送る標準CAN ID | BOOT操作で0x100～0x10Fから選び、データフラッシュへ保存 |

CAN IDは本来フレームの識別子です。このテストでは機器ごとに1個を割り当て、「ノードの通信ID」として扱います。管理通知には別の拡張CAN IDを使います。

## 状態と操作

| state | 名前 | 動作 |
|---:|---|---|
| 0 | Unset / 未設定 | 通信IDは0xFFFF。通常データを送らず、管理通知は継続 |
| 1 | Scanning / 探索 | 相手の通知と標準IDの受信履歴から空きを調べる |
| 2 | Claiming / 候補確認 | 候補IDを通知し、他機器との競合を確認 |
| 3 | Assigned / 設定済み | 保存IDで通常のテストデータを送信 |
| 4 | Error / エラー | 通常データを停止。管理通知とエラー表示は継続 |

起動時は、保存レコードが有効なら設定済み、未設定・不正なら未設定になります。設定済みでも、起動後3秒は通常データを待ち、管理通知による重複検出の時間を設けます。

BOOT入力は押下時LOWです。入力が25ms安定した時点で押下・解放を確定し、チャタリングを抑えます。1回押しは約0.5秒待って確定し、0.5秒以内の2回目の押下があれば2回押しとして扱います。押したままでは繰り返し発火しません。

- 未設定で1回押すと探索を開始します。設定済み・探索中・エラー中の1回押しは無視します。
- 2回押すと、どの状態からでも保存IDを未設定へ変更します。検出エラーも解除します。
- CAN初期化が失敗している場合は、2回押してもCAN異常へ戻ります。CANの再初期化処理はありません。
- 2回押しはMCUのリセットではありません。送信連番と累積カウンターは維持されます。

## 最小の空きIDを選ぶ

1. 探索開始から1.5秒間、通信できる相手の状態を集めます。
2. 0x100から順に、次のいずれにも当てはまらないIDを選びます。
   - 生存している相手が設定済み、エラー、または候補確認中として通知したID
   - 過去3秒以内に標準CANフレームを受信したID
3. 候補を1.5秒間通知します。競合しなければ設定済みへ移り、IDを保存します。
4. 候補確認中に既存所有者を見つけた場合は、候補を取り下げて再探索します。
5. 同じ候補を選んだ機器同士では、全128ビットUIDをバイト列として比較し、小さいUIDを優先します。敗れた側が再探索します。

同時操作では再探索が入るため、割当時間は一定ではありません。管理通知は周期送信であり、専用の問い合わせ・応答メッセージを送る方式ではありません。

割当範囲に空きがない場合は、エラー4になります。範囲はFIRST_ID=0x100、COUNT=16で定義しています。現在の管理フレームはID番号を1バイトに格納するため、定数だけを大幅に広げる使い方には対応していません。

## 衝突時は送信を停止する

設定済みの機器が、別UIDから同じIDの所有通知を受けるとID重複として停止します。エラー状態の所有通知も対象です。また、通常CANモードでは自分の送信を受信キューへ戻さない前提で、自分と同じ標準IDを受信した場合も重複と判定します。

候補確認中に同じ標準IDを受信した場合は、エラー停止せず候補を取り下げます。

重複時に保存IDを自動消去することはありません。一方のBOOTを2回押して解除し、1回押して再登録してください。エラーは最初に検出したものを保持し、その後の別エラーで上書きしません。

## LEDは状態とIDを示す

| 状態 | パターン |
|---|---|
| 未設定 | 赤300ms点灯、300ms消灯 |
| 探索・候補確認 | 黄200ms点灯、200ms消灯 |
| 設定済み | 10秒周期で青300ms→消灯300ms→緑の回数表示 |
| エラー | 赤をエラー番号の回数だけ点滅して繰り返す |

設定済みの緑点滅は`通信ID - 0x100`回です。各回は200ms点灯、300ms消灯です。0x100では緑を出さず、青だけを表示します。周期は各機器の起動後時刻を基準とし、機器間で同期しません。

全色にsetBrightness(26)を適用しています。元の色成分24は丸め後に2、黄の16/12は1/1となります。設定値は元の色設定に対して約10%であり、最大輝度・見た目・装置全体の消費電力の10%を保証するものではありません。

### 赤の回数とエラー番号

| error | 意味 | 主な確認項目 |
|---:|---|---|
| 0 | エラーなし | 通常状態 |
| 1 | 通信IDの重複 | 他の機器の保存ID、接続した機器の構成 |
| 2 | CAN初期化失敗、またはBus-offが2秒以上継続 | 給電、GND、配線、終端、トランシーバの版・制御端子 |
| 3 | 保存後の読み戻し検証失敗 | データフラッシュ、保存中の電源 |
| 4 | 空きIDなし | 範囲内の機器数と使用ID |
| 5 | UIDハッシュの衝突 | 管理用タグと全UIDの比較 |
| 6 | 相手機器の管理テーブルが満杯 | 機器数、予約した管理IDを使う他システム |

エラー表示は赤160ms点灯、400msごとの枠で指定回数を表示します。その後の1.4秒を含め、周期は`error × 400 + 1400`msです。

## データフラッシュへIDを保存する

EEPROMライブラリを通して、論理アドレス0～7の8バイトを使用します。XIAO RA4M1では実体は内蔵データフラッシュです。

| オフセット | サイズ | 内容 |
|---:|---:|---|
| 0 | 4バイト | 識別子と形式バージョン：0x58434E01 |
| 4 | 2バイト | 通信ID。未設定は0xFFFF |
| 6 | 2バイト | 通信IDのビット反転値 |

RA4M1上の保存はリトルエンディアンです。識別子、反転値、ID範囲が一致するレコードだけを採用します。不正な値は未設定として扱い、起動するだけでは上書きしません。

保存するのは登録・解除のときだけで、同じ値なら書き込みません。保存後は読み戻して確認します。他のアプリケーションでEEPROMを使う場合は、この保存領域と重複させないでください。

書込み中の電源断に備えたレコード二重化はありません。保存途中に電源が切れると、次回は未設定になる可能性があります。フラッシュ全消去でも設定は失われます。

## 検出できる範囲

電源OFF・分断中の機器が保存しているIDは予約できません。占有情報は最後の受信から3秒で失効するため、後から戻った機器と重複する場合があります。その場合は重複エラーとして扱います。

同じスケッチの機器は、通常データを送らない状態でも管理通知を出します。他のプログラムを使う機器については、探索中に受信した標準IDだけが分かります。沈黙中の機器のIDを調べる機能はありません。

管理通知の送信元識別は25ビットUIDハッシュです。全UIDの復元後にハッシュの整合を確認しますが、同じタグの機器が同時送信すると、全UIDを復元する前にCANエラーになる可能性もあります。暗号による認証や、あらゆるUIDで衝突しない送信元アドレスは実装していません。

## 用語

- 候補確認：まだ保存していないIDを相手へ通知し、競合がないか待つ段階。
- Bus-off：CANコントローラーが通信エラーの増加によってバスから離脱した状態。
- ACK：CANフレームを受信したコントローラーが返す確認。相手のアプリケーション処理完了とは別。
- 永続保存：電源を切っても保持される保存。本スケッチではデータフラッシュを使用。
