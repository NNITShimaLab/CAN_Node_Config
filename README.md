# XIAO RA4M1 CANノードID設定テスト

複数のXIAO RA4M1をCANで接続し、BOOTボタンで通信IDを設定するArduinoスケッチです。同じコードを全台に書き込み、稼働中のネットワークから最小の空きIDを選んで保存します。機器ごとの固有IDをコードへ登録する必要はありません。

約10台の利用を想定し、現在は標準CAN IDの **0x100～0x10F（16個）** を使用します。

初めて使う方は「必要な機器」から「BOOTボタンでIDを設定する」までを確認してください。CANの送受信形式やシリアルログを解析する方は、別の仕様書を参照してください。

## 必要な機器

- Seeed Studio XIAO RA4M1：2台以上を推奨
- CAN transceiver board for XIAO RA4M1：各XIAOに1枚
- CANH、CANL、GNDを接続する配線と、両端の終端抵抗
- Arduino IDE、またはArduino CLI

CAN transceiver board for XIAO RA4M1は、基板裏面に **`7012760A_Y5_241018`** と記載されているものを使用してください。接続前に、基板裏面のIDを確認してください。

### ピンの接続

| XIAO端子 | 接続・用途 |
|---|---|
| D10 / P109 | TCAN330の1番TXDへ接続 |
| D9 / P110 | TCAN330の4番RXDから入力 |
| D8 / P111 | TCAN330の8番Sへ接続。スケッチでLOWに設定 |
| 3V3 | トランシーバ基板の3.3V電源 |
| GND | 共通GND |
| Arduino pin 26 / P201 | XIAO内蔵BOOTボタン。押下時LOW |
| Arduino pin 20、21 | 内蔵RGB LEDの信号、電源有効化 |

CANの通信速度は250kbpsです。電源の供給方法は、使用するXIAOとトランシーバ基板の回路に合わせてください。

## 同じスケッチを各XIAOへ書き込む

開発時に使用した環境は、SeeeduinoのRenesasボードパッケージ1.2.0とAdafruit NeoPixel 1.15.4です。Arduino_CANとEEPROMはボードパッケージに含まれています。

### Arduino IDE

1. Seeedのボードパッケージを導入し、ボードに「XIAO RA4M1」を選びます。導入方法は[Seeed公式ガイド](https://wiki.seeedstudio.com/getting_started_xiao_ra4m1/)を参照してください。
2. ライブラリマネージャーで「Adafruit NeoPixel」をインストールします。
3. [CAN_Node_Config.ino](CAN_Node_Config/CAN_Node_Config.ino)を開きます。同じフォルダーにあるNodeConfig.hも必要です。
4. 対象のUSBポートを選び、各XIAOへ書き込みます。

機器ごとのビルド設定や、ノード番号の指定は不要です。

### Arduino CLI

このREADMEがあるディレクトリで実行します。ボードパッケージとライブラリがインストール済みであることが前提です。

```sh
arduino-cli lib install "Adafruit NeoPixel@1.15.4"
arduino-cli compile --fqbn Seeeduino:renesas_uno:XIAO_RA4M1 --output-dir build CAN_Node_Config
```

ボードの追加URLはSeeed公式ガイドを参照してください。コアのFQBNは`Seeeduino:renesas_uno:XIAO_RA4M1`です。書き込むUSBポートは環境によって異なります。

## BOOTボタンでIDを設定する

BOOTボタンは、スケッチが起動した後に操作します。押したまま電源投入・リセットすると、XIAOのブートモードに入ります。

1. 未設定の機器では、赤LEDが点滅します。
2. BOOTを1回押します。約0.5秒で単押しを確定し、通常はさらに約3秒で探索・候補確認・保存が完了します。
3. 最初の機器には0x100が割り当てられます。次の機器で同じ操作をすると、0x101以降の最小の空きIDが割り当てられます。
4. IDを解除する場合は、BOOTを0.5秒以内に2回押します。赤点滅へ戻った後、1回押して再登録します。

設定済みの機器を1回押しても、IDは変わりません。保存IDは、次の起動時に読み出されます。ID解除は保存設定の解除であり、MCUの再起動ではありません。

### LEDの読み方

| 表示 | 意味 |
|---|---|
| 赤の通常点滅 | ID未設定 |
| 黄の点滅 | 空きIDの探索・候補確認中 |
| 青だけ、10秒周期 | ID 0x100 |
| 青→緑1回、10秒周期 | ID 0x101 |
| 青→緑2回、10秒周期 | ID 0x102 |
| 青→緑N回、10秒周期 | ID 0x100 + N |
| 赤の回数表示 | エラー。回数の意味は動作仕様のエラー表を参照 |

青300ms、消灯300msの後、緑を200ms点灯・300ms消灯で指定回数表示します。LEDは`setBrightness(26)`で元の色設定の約10%へ減光しています。装置全体の消費電力や、人が感じる明るさの比率を示す値ではありません。

### シリアルで状態を確認する

USBシリアルを115200bpsで開くと、約1秒ごとに次の形式で出力します。以下のUIDは説明用の架空値です。

```text
UID=00112233445566778899AABBCCDDEEFF state=3 ID=0x100 error=0 rx=42 tx_failed=0 TEC=0 REC=0
```

`state=3`は設定済み、`error=0`はアプリケーション側の検出エラーなしです。`rx`は受信したテストデータの累積数、`TEC`と`REC`はCANハードウェアのエラーカウンターです。詳しい定義は[通信仕様](docs/通信仕様.md)に記載しています。

## 検証済みの範囲

2026年10月15日時点で、XIAO向けビルドとPC上の状態機械テストを確認しています。PCテストでは10台同時登録、重複検出、最小空きID、ボタン判定、LEDの0～15回表示などを検証しました。

実機2台では、BOOT操作後の0x100/0x101への登録をログで確認しました。同じバイナリの再書込み後も保存IDが保持され、双方の受信数が増加し、送受信エラーカウンターが0へ戻ることを確認しています。

10台の実機試験、2回押しによる解除、実機での衝突表示、LEDの目視、電源断中の保存、消費電流の測定は未確認です。試験方法は[試験手順](docs/試験手順.md)にまとめています。
